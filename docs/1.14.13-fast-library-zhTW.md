# LumiBase Fast Library 1.14.13

## 縮圖真平行解碼、已編輯 JPEG 裁切支援與高光著色器數值防護

本版本針對 v1.14.11 / v1.14.12 的盲點進行深層修復，包含縮圖佇列並行化、已編輯非 RAW 檔案縮圖裁切、高光著色器數學防護，並清理 README 專案結構。

### 1. 縮圖解碼隊列真正平行化 (`ThumbnailLoader`)
- **問題分析**：先前版本雖然移除了 `editedTail` 隊列，但 `ThumbnailLoader.decodeQueue` 宣告時未指定 attributes，底層依然是 GCD 單執行緒的 Serial Queue，導致解碼實際上仍是一張一張排隊。
- **修復方式**：
  - 將 `decodeQueue` 宣告配置 `attributes: .concurrent`，回歸真正的多核心平行排程。
  - 引入 `DispatchSemaphore`，依硬體 CPU 核心數限制並行數（`min(4, max(2, ProcessInfo.processInfo.activeProcessorCount))`），在平行加速的同時防止快速滑動造成記憶體暴增。

### 2. 已編輯非 RAW（JPEG）縮圖裁切與調色支援 (`ThumbnailLoader`)
- **問題分析**：原判斷式限制為 `if asset.isRaw && asset.xmp.hasDevelopEdits`，若使用者裁切了 JPEG 檔案（如 2:3、16:9），因非 RAW 檔而略過處理直接讀取原圖，導致縮圖未反映裁切。
- **修復方式**：
  - 將條件改為 `if asset.xmp.hasDevelopEdits`，不論 RAW 或非 RAW（JPEG/HEIC/TIFF），只要有編輯皆送進 `AdobeColorPipeline.shared.process` 套用裁切框（Crop Box）、旋轉角度與色調調整。
  - 快取版本升級為 `fast-accurate-v4`，自動作廢並刷新舊有的未裁切縮圖。

### 3. 高光著色器（AcceptedHighlightsKernel）數學溢位徹底根治
- **問題分析**：先前僅將偏好設定預設改為 `false`，但著色器 Kernel 在日落直射、高反差強光處，`exp2(d)` 無邊界會引發指數爆炸，且色相奇異點除零與負數邊界計算會導致黑太陽、霓虹綠與階調分離。
- **修復方式**：
  - **CPU 端 (`prepare`)**：嚴格限制 `guide`、`detail` 與 `correction[i]` 數值於 `[-3.0, 3.0]` 穩定區間，避免回歸係數暴衝。
  - **GPU 端 (`colorKernel`)**：
    - 將 `correction.r` 嚴格限制在 `[-3.0, 3.0]`，使 `exp2(d)` 永遠落在 `[0.125, 8.0]` 安全範圍。
    - 修復 `invlab` 輸出邊界 clamp，防止產生非法負數。
    - 修復色相計算的零除奇異點，改採穩定之正切角度算式。
    - 修正高光極限邊界算式，防止過曝像素（$y > 1.0$）在計算 `1.0 - y` 時產生負值造成色彩反轉。
    - 最終像素強制 `clamp(outc, 0.0, 1.0)`，徹底杜絕 NaN 與色階斷裂。

- 清理 `README.md`，移除歷代版本的修改紀錄雜項，回歸乾淨的產品介紹與核心特色展示。
