# LumiBase Fast Library 1.14.12

## 預覽即時滑動、平行縮圖與高光著色器修復

本版本針對 v1.14.10 / v1.14.11 回歸引入的預覽畫面黑屏轉圈、縮圖序列卡死、已編輯 JPEG 未裁切及高光著色器數學溢位問題進行徹底修復。

### 1. Develop 模式拖動滑桿黑畫面轉圈修復 (`LoupeView`)
- **根本原因**：`LoupeView` 的 `.task(id:)` 監聽了 `appState.primarySelectedAsset?.xmp.thumbnailDevelopCacheIdentity`。每次拖動 Highlights、Shadows 或 Exposure 滑桿，該 task 即被中斷並重新執行 `loadSelectedImage()`。在此函式內部，`InspectionDisplay.beginSelection()` 強制將目前顯示的點陣圖設為 `nil`（全黑畫面）並開啟 `isLoading = true`（菊花轉圈），同時銷毀已快取的 `currentBaseHolder`。
- **修正方式**：
  - 從 `.task(id:)` 中移除 `thumbnailDevelopCacheIdentity`。數值調整回歸由 `.onChange(of: appState.liveDevelopXMP)` 與 GPU `LiveDevelopPreviewEngine` 進行即時演算（最高達 120fps）。
  - 在 `InspectionDisplay.beginSelection` 與 `InspectionLoadTransition.beginSelection` 增加 `preserveCurrent: Bool = false` 支援；編輯同一張照片時保留現存影像，不重設為 `nil` 也不進入 `isLoading` 狀態。
  - 保留同一選取目標的 `currentBaseHolder`，避免調色過程反覆釋放並重複完整解碼。

### 2. 縮圖平行解碼與已編輯 JPEG 裁切修復 (`ThumbnailLoader`)
- **佇列平行化**：先前 `decodeQueue` 未配置 `attributes: .concurrent` 實質為 serial queue，且 PR #11 加入之 `editedTail` 形成額外序列鎖。現改為具上限的並行隊列（`attributes: .concurrent` 搭配 `DispatchSemaphore` 依 CPU 核心數限制平行並行數），既達成真正的多工平行載入，又防範大量照片同時解碼造成的記憶體飆升。
- **已編輯 JPEG / 非 RAW 縮圖支援**：修復先前縮圖只處理「RAW + 有編輯」，導致已編輯之 JPEG 檔案直接讀取磁碟原圖、略過裁切與調色的錯誤。現不論 RAW 或 JPEG，只要含有 XMP 編輯（如 2:3、16:9 裁切、曝光微調），皆會進入 `AdobeColorPipeline.shared.process` 套用正確的裁切外框與色調後再生成縮圖。
- **快取更新**：將快取鍵版本更新為 `fast-accurate-v4`，自動淘汰先前未裁切或有瑕疵的縮圖快取。

### 3. 高光著色器核心數學溢位修復 (`AcceptedHighlightsKernel`, `NativeHighlightsService`)
- **根本原因**：先前僅將 `NativeHighlightsService.isEnabled` 預設值設為 `false`，但核心 `AcceptedHighlightsKernel` 的著色器與引導場在遭遇極高動態範圍（如大逆光、太陽直射）時，`exp2(d)` 指數未設防護造成浮點數極大值，且色彩空間轉換在純黑邊界與亮部邊界處發生奇異點與負數邊界計算，導致高光區太陽反黑、邊界呈霓虹綠色階斷裂。
- **修正方式**：
  - 在 `prepare` 引導場計算中對 `log2` 輸入與輸出進行嚴格 clamp，限制回歸權重與修正項 `correction[i]` 於 `[-3.0, 3.0]` 穩定區間。
  - 在 `colorKernel` GPU 著色器中：
    - 將 `exp2(d)` 限制在 `[-3.0, 3.0]` 範圍內，防止指數爆炸。
    - 對 `invlab` 輸出加上安全邊界 clamp，防止虛數或極端值。
    - 修復色相計算中的零除問題，改採穩定之正切角度算式。
    - 修正邊界限制計算（`delta` 與 `bound`），防止高於 1.0 的過曝亮部在計算 `(1.0 - y)` 時產生負數造成色彩反轉。
    - 最終輸出統一以 `clamp(outc, 0.0, 1.0)` 防護，徹底杜絕 NaN、極黑太陽或螢光溢色。即使使用者手動開啟 Native Highlights，亦能穩定運作。

### 4. 照片網格項目切換時的主預覽洗白修復 (`PhotoGridItemView`)
- **根本原因**：`loadThumbnail()` 於啟動時執行 `if isPrimary { onPreview(nil) }`，導致每次縮圖刷新皆將主視窗已渲染的預覽圖清除。
- **修正方式**：
  - 移除強制清除 `nil` 的邏輯，已有縮圖時不重複顯示進度條，並於主佇列非同步派送 `onPreview`，消弭 SwiftUI purple warning。
