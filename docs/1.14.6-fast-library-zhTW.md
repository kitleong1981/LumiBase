# LumiBase Fast Library 1.14.6 — JPEG ROI ±1 實驗（預設 OFF）

## 如何試用

在 **Library → Loupe** 的照片工具列，點 **`JPEG ROI ±1 OFF · EXP`** 切成 ON。這是獨立的 Library JPEG 鄰張快取，不是 Develop 的 RAW ROI 按鈕；只保留前 1／後 1，沒有 ±2。開關只存在這次 Loupe session，不寫入既有 profile 偏好，不自動啟用。

目前照片完成原生 100% 後才預存相鄰 JPEG。切到鄰張时，若來源版本、檢視幾何、方向／完整尺寸及 ROI 覆蓋相符，先顯示這張照片自己的原生 ROI，再由既有前景 queue 準備完整 JPEG。平移離開覆蓋時回到同張照片預覽／已完成原生圖，不冒充完整原生。Fit、mode、selection／方向與 geometry 變動取消舊排程；不可中斷的 helper 可以完成，但舊結果不得發布，也不佔用前景 native queue。

左鍵按住暫時 100%、放開回 Fit，雙擊／Z 明確持續縮放、1.14.5 Trash 確認保留 hold／release 取消均維持；Develop RAW ROI、histogram-off 與既有小型預覽／native cache 的設定不改。

## 記憶體隔離

- 鄰張只接受匹配 companion JPEG 或選取的 JPEG；RAW-only／未驗證 embedded preview 不加入這個實驗，不觸發 RAW fallback。
- 獨立 utility serial worker，每次啟動一個隨 App 封裝的 **Swift／ImageIO native helper**。helper 完整解碼、依 oriented source extent、normalized center、backing 與 256px 四邊 overscan 取像素，輸出緊密 RGBA8，然後退出。**不是 JPEG 部分解碼**。
- App 用 POSIX pipe 直接讀進最終 `CGDataProvider` buffer，provider release callback 釋放並計量 owned bytes。沒有 neighbor full JPEG 放入既有 2 張／512 MiB native cache。
- 鄰張 cache 最多 **2 entries／64 MiB**，包含 ROI 與同張 1600px fallback preview 的實際 bitmap cost。前一張可能尚無方向性預覽，或 handoff LRU 已淘汰它；必須把小型 fallback 一起保留，不能平移後露出裸 crop 的黑邊。這只是 cache pixels 的限制，不是 App RSS 或目前顯示 frame／helper transient 的限制。
- 新探測曾失敗：in-process owned-provider copy 16 cycles 最後約 5.31 GB RSS；改成 helper 但使用 Foundation 大型 `Data` pipe 仍每 cycle 增長約 48 MB。最終直接讀入 owned buffer、包含安全 fallback 的 3 trials，各 16 cycles（32 次 decode）在約 **186.50–186.61 MiB** parent RSS 平台；後半變動範圍 <0.6 MiB，沒有每 decode 線性增長。cache bytes 固定 **61,674,752**（其中 ROI owned bytes **47,991,552**）；clear 後 ROI owned bytes **0**，但既有 thumbnail cache 與 allocator RSS 不會立刻回 baseline（baseline 22.78–22.80 MiB）。不能把殘留 RSS 說成仍有活的完整 JPEG backing。
- 單次 helper 額外完整解碼 peak RSS **750,583,808 bytes**（`time -l`），退出才保證釋放其完整 backing。App 既有 selected native／SwiftUI 部分的總 RSS 仍很高，這個實驗沒有替整個 App 設硬上限。
