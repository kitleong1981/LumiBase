# LumiBase Fast Library 1.14.9

## Sharpness 改用實際全圖像素

右下角改為 **Sharpness · Full resolution**，後面標示 `Native JPEG`、`Native RAW` 或 `Processed` 與真正輸入尺寸。

- 未編輯 Library：優先借用版本匹配的原生 JPEG memory cache；沒有暖圖時，在獨立 utility 序列 worker 解碼匹配的原始 JPEG。RAW 的內嵌 JPEG 必須與原始影像尺寸相符，否則只對當前選取 RAW 準備 accurate full source。1600px camera preview 不會放大冒充 full resolution。
- 已編輯／Develop：相同 XMP 曝光、色調與 crop 的 **full processed output**；裁切後的全輸出也標示實際尺寸。不是 viewport ROI，也不會把原始未編輯圖的分數標成 Processed。Before／comparison 暫不提供指標，以免混淆來源。
- 保留 64px Laplacian blocks、最銳利 10% 平均的相對公式，只移除 1024px 採樣並修正來源。沒有加入新的 ROI 演算法、對焦信心、自動淘汰或通用分數門檻；雜訊、銳化、曝光、crop 都會影響值。
- 新偏好設定預設 OFF；沿用 `previewSharpnessEnabled`，既有 ON 意圖不被重設。⌘, → **Sharpness / Full resolution — Experimental** 說明額外解碼成本。

## 排程、取消與記憶體

顯示圖 publication 只用來啟動排程，**不把 display/proxy/ROI bitmap 當 score 輸入**。first-ready／native-ready 不等待分數。首次工作先有 150ms 可取消的 idle grace，讓立即要求 100% 的前景請求先行；這不是分數計算耗時。

同時只有一個 active selected job＋一份 latest pending **metadata**。切換選取、來源 revision、修圖、workspace／view mode、Highlights policy 或 OFF 時取消並拒絕過期 publication；queued 狀態顯示 preparing，來源無法驗證則 unavailable，不保留過時值冒充目前版本。scalar result cache 最多 256 筆，不儲存 full bitmap／CI graph。RAW decode／processed raster 使用 GCD 與前景優先的共享 gate，不在 Swift cooperative worker 上等待 decoder；前景原生請求可以優先於尚未開始的背景工作，但已開始的系統解碼／GPU render 不能搶先中斷。

完整 source／output 上限 128×1024×1024 pixels、每軸最多 32768；在 RAW preparation 前也查來源 metadata，超限明確 unavailable。score 的 explicit owned buffers 是一張暫存 full bitmap（若借用 native cache，這部分為零）＋一張 8-bit 灰階圖；score 自己的 CIContext 不快取 intermediates。這**不是 process RSS 的硬上限**：Apple decoder、RAW float graphs、GPU／allocator 暫存另計。60MP 的 9504×6336 灰階為約 57.43 MiB；新解碼 RGBA＋灰階約 287.14 MiB，借用 native cache 時新增約 57.43 MiB。既有 native cache 2 張／512 MiB、proxy 12 張／96 MiB 沒有擴大；JPEG ROI cache/helper 為不同機制，helper full decode 的歷史瞬間約 750 MB 不能算進 score buffer 上限。

## 實測（不可當固定保證）

唯讀的同一組 DSC01801／DSC01803 JPG／ARW 複本：原生 JPEG **9504×6336** 的分數分別 **131.4213／439.5307**，不再是 1600→1024 proxy 的 2747／2894。RAW-only reduced embedded 不被冒充原生；actual Native RAW 9504×6336 通過。曝光＋中央 crop 的 RAW 產生 **Processed 4752×3168**，也是 full output 而非 ROI。

單獨 cold-source 其中一輪：JPEG compute 147.87／157.56ms，額外 source decode 157.27／147.25ms；RAW-only compute 264.17ms、source/render 607.99ms；edited RAW crop compute 68.81ms、source/render 172.17ms。這些是本機該次觀察，不是 SLA。最後 delivery 複驗亦保留：1801 compute 157.59ms／CPU 156.47ms、load 174.66ms；1803 wall 832.74ms／CPU 129.16ms、load 46.74ms，出現額外排程延遲；RAW-only compute 468.55ms／load 2798.98ms、crop 158.06ms／load 243.72ms。不能只以最佳 122ms 代表全部操作。先前使用者接受的 **122–131ms 是舊診斷**，不是新版本整體 source-load＋compute 保證。

實際 NSHostingView／NSWindow，兩張 60MP JPEG＋一張 in-memory exposure RAW，Grid→Loupe→立即 native→Fit→快速切圖。完整未計入 OFF／ON warmup 後，三輪交替序列；native 請求在等待 score **之前**發出。OS caches 未清空，無其他本次測試 render 並行。下列為 delivery source 的最後三輪測量（借用 native pixels 已獨立計帳）；全部序列執行。
