# LumiBase 1.12.1：Backspace 確認與 RAW 原生基準曝光

此修正從 upstream/main 1.12.0 建立，只包含下列兩項功能及刪除安全性。保留 upstream bundle ID `com.lumibase.LumiBase.Inspection.ROI`，不加入 PhotoCraft 的 tone、鏡頭或 Contrast 實驗。

## Backspace 刪除確認

在照片格子、Loupe 或底片列點選取得照片區域焦點後，直接按 Backspace（macOS keyCode 51）會開啟與 Command+Backspace 相同的刪除確認，不會立即刪除。取消確認會保留照片。確認視窗開啟時，Return 與其他按鍵交由視窗本身處理。

搜尋、文字、數值、檔名編輯欄位與文字編輯器中的 Backspace 不會觸發照片刪除。點選照片區以外會解除焦點；有 sheet、同步／複製設定對話框或控制項焦點時，不接受單獨 Backspace。Shift、Option、Control 組合不會當成此快捷鍵。

確認後僅呼叫 macOS Trash。Trash 失敗會顯示錯誤，保留失敗資產及其選取狀態，**不會退回永久 removeItem 刪除**。RAW/JPG/XMP 等關聯檔案不是原子交易：部分關聯檔可能已成功移至垃圾桶，請先在 Finder 還原，再重試。

## RAW 每檔案原生基準曝光

RAWImageLoader、PhotoExportService 及既有 NativeHighlightsService 不再把 `CIRAWFilter.baselineExposure` 覆寫成固定 0.30。此值是解碼器依每個檔案提供的絕對基準，不是使用者的 +0.30 EV 曝光補償。保留原生值可避免高 baseline 的 RAW 異常變暗；低 baseline 檔案也不再被固定值額外提亮。

只移除 baseline 覆寫，其餘白平衡、shadow、boost、使用者曝光與既有 tone policy 不變。NativeHighlightsService 的變更只讓既有 endpoint 保留相同原生 baseline，沒有引入新高光功能。這不保證 RAW 與相機 JPG、縮圖或 Lightroom 完全一致，也不解決 Apple gain-map 相容性或相機 ISP／HDR 差異。

可在有唯讀樣本的環境補跑：

```sh
LUMIBASE_NATIVE_BASELINE_VALIDATION=1 \
LUMIBASE_NATIVE_BASELINE_FIXTURES='/path/to/fixture-root' \
LUMIBASE_NATIVE_BASELINE_OUTPUT='/path/to/separate-output' \
swift test --filter NativeBaselineExposureTests
```

fixture root 應含測試內列出的 ZF7 與 Luna 三個 DNG；輸出必須是與來源不同的目錄。此 opt-in 測試驗證原生 baseline、production loader、full-resolution export、thumbnail 與既有 native highlight endpoint。建議執行前後對來源 DNG/JPG 計算 SHA256，確認來源未變。
