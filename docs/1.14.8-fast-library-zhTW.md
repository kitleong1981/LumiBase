# LumiBase Fast Library 1.14.8

## Settings 的 Esc 與鍵盤歸屬修正

- Settings 視窗在前景時，**Esc 關閉 Settings 本身**，不切換主照片視窗到 Grid、不清除選取、不改變既有持續 100% zoom，也不退出 App。
- 原本 App-wide `NSEvent` key monitor 不分來源視窗，會在 Settings 攔截 Esc（甚至 Z、G、方向鍵）並修改主視窗。現在只在該 AppState 的照片工作區視窗為 key、事件確實來自該視窗、沒有 attached sheet 時執行主視窗快捷鍵。
- Settings 內文字編輯器與正在 tracking 的原生選單優先保留標準 Esc 取消行為；關閉的是 Settings，不是整個 App。Trash sheet 的 Return/Esc 與按住檢視確認流程維持原樣。
- 主照片視窗取得焦點時，Esc 保持原有 Loupe→Grid／Grid 取消選取行為。

## ROI 顯示 0 並不是這個錯誤

JPEG ROI 鄰居快取只在 **Library、未編輯且有 JPEG、當前完整 native 100% 已完成**時產生；±2 最多四個鄰居。Grid／Fit 不會建立；返回 Fit、放開臨時按住、工作區切換或 App deactivate 會取消並清空。Settings 顯示的是目前保留的 entries／bytes，不是累積使用量。

若使用按住左鍵 100%，開啟 Settings 所造成的主視窗失去 key 會結束臨時按住並回 Fit，因此顯示 0 合理。若要檢查快取，設定 ±2／128 MiB 後，在符合條件的照片按 **Z** 進入持續 100%，等待 native 完成與 utility 鄰居工作，再開 Settings；不要先切回 Fit。已編輯照片使用準確 RAW 處理，不加入 JPEG ROI。

沒有放寬 Fit／mode／deactivation 記憶體釋放約定，也沒有用累積數值冒充目前快取。

## 驗證與限制

- 預設完整 Release：229 tests、34 skipped、0 failures。新增鍵盤測試需 bundled AppKit host 才能取得真正 key window，另行執行，非宣稱在 headless swift-test 中通過。
- 相同 native NSHostingView + 真實 NSWindow + `NSApplication.sendEvent` regression：移除修正時 7 assertions 失敗；修正後 1 test／0 failures。驗證持續 100%、選取／view mode 不變、Settings 關閉、主視窗 Esc、原生文字取消與 menu-tracking gate。選單 tracking gate 使用原生通知注入，不冒稱實體 popup click QA。
- 可攜式命令（scratch 必須指定可寫的測試區域）：

```sh
swift test -c release
LUMIBASE_NATIVE_TEST_SCRATCH=/path/to/authorized/scratch bash scripts/test_settings_keyboard_native.sh
```
