# LumiBase Fast Library 1.14.5（本機測試版）

## 這版修正

- 左鍵仍按住 100% 時開啟「Move to Trash」確認，不再因確認視窗取得鍵盤焦點而跳回 Fit。
- Enter 確認後沿用現有背景 Trash 流程並選下一張；尚未放開左鍵時保留暫時 100%，不顯示被刪照片冒充下一張。
- 在確認中或確認後放開左鍵（含視窗外），仍立即回 Fit；不改成單擊鎖定。雙擊／Z 的明確持續縮放行為不變。
- 真正切換到其他 App、關閉視窗、切換 Library／Develop 仍清理暫時按住與滑鼠事件監聽。
- 修正僅涉及原生手勢焦點生命週期；Trash 確認、背景檔案安全機制與 Develop RAW 處理未變。

## JPEG 鄰張 ROI 預存：尚未交付，不預設啟用

本版沒有加入前後 1 張的原生 ROI 預存，也沒有加到前後 2 張。保留 1.14.4 的小型 1600px 方向性預覽、12 張／96 MiB handoff 與原生 2 張／512 MiB cache 設定。

先做了唯讀 ImageIO 服務探測：三張 9504×6336 JPEG，各自完整解碼像素為 240,869,376 bytes。直接 `CGImage.cropping` 的 2712×1992 小視窗，三張保留後程序 RSS 仍約 742 MB，沒有證明底層完整 JPEG 儲存已釋放；以 CGContext 重畫的小視窗雖名義像素只有每張 21,609,216 bytes，三次序列探測 RSS 仍約 807 MB。這是程序 RSS，不是 cache 常駐成本；尚未隔離 ImageIO／allocator 的保留行為。因此不能只按 ROI 尺寸宣稱記憶體已受到硬限制，更不能宣稱 JPEG 部分解碼或消除完整解碼峰值。

探測只建立測量／安全阻礙，**不是**完整 ±1 功能、hosted ROI 命中測試或前景前後效能比較。本版不宣稱 ROI 加速、零延遲或 60 fps。

## 實測與限制

- 新增 generated JPEG + 注入 fixture Trash 的 hosted Loupe 測試。舊程式在確認取得焦點、監聽存續、確認後保持 100% 三處皆 RED；修正後 GREEN。實際附加 NSAlert sheet，以 Return 的原生 default button key-equivalent 呼叫相同確認 callback；另驗證確認中放開、確認後視窗外放開及下一張 ID／完整幾何。沒有對 A7RV 做刪除、評分或 XMP 寫入。
- 完整 Release：209 tests，27 skipped，最終 0 failures。第一次有既存 hosted wheel 下一張斷言失敗；原樣重跑成功，未放寬門檻。
- 唯讀 A7RV hosted native hold：9504×6336 原生 JPEG、backing 2、原生 publication 194.82 ms；empty／spinner samples 均 0。實際 viewport heartbeat p95 82.81 ms、max 191.99 ms（門檻仍為 250 ms）。不是 compositor 呈現延遲。
- Mounted handoff 測試唯一失敗是固定 739 張數量斷言：執行時已是 727 張。調查開始檔案已非委派的 1478 files，而是 1472 files；後續仍有使用者工作變動。沒有補資料、還原刪除或放寬 739 門檻，因此不能宣稱既定 739 張 mounted 套件全數成功，也不能建立同一暖機條件下 ±1 的可靠比較。
