## Library 與 Develop

上方有明確的 **Library / Develop** 切換器；每次啟動預設 Library。

### Library：穩定相機預覽，快速挑片

- Fit 主圖、Grid 與 Filmstrip 使用 camera JPEG。RAW 優先取內嵌 JPEG；沒有內嵌預覽時才取 scanner 配對、同資料夾、同 basename 的 JPG/JPEG。任意鄰近 JPEG 不可代替該 RAW。
- RAW 路徑不使用 `CreateThumbnailFromImageAlways`／`FromImageIfAbsent` 產生 RAW 解碼 fallback。沒有可信候選時顯示預覽不可用，請明確切至 Develop；不偷偷啟動 accurate RAW／refine。
- 主圖標示 **Camera preview (JPEG)**。已有 Develop／crop edits 的照片另標 **Edited — edits not displayed**；Grid／Filmstrip 有 Edited badge。
- **Library 刻意不呈現 Develop 調整／crop 顯示結果，但保留全部 XMP、評分、旗標、關鍵字等 metadata。** 切到 Develop 即套用既有 edits，並不是清掉 edits。
- Camera JPEG 和 Apple RAW＋現有色彩流程的 WB、tone、亮暗可能不同；不能把兩個模式的亮度差直接判斷為曝光錯誤。配對 JPEG 是 scanner 的同名配對，不是對相機 ISP 或使用者曾覆寫的 JPEG 做真實性認證。
- Library 的編輯／同步／Reset 面板受模式限制；可用 **Open Develop for editing**。Crop／Before-After 快捷操作會進入 Develop，既有 G／E Grid／Loupe、箭頭挑片、X 旗標、評分、Backspace 確認仍保留。
- 現有 **100%／Space inspection** 可以明確請求 native RAW＋edits，並顯示 native/ROI 100% 狀態。回 Fit 再回到 camera JPEG。沒有新增使用者暫緩的 100% optional preview panel。
- 切模式／Reset 更新 source revision、清除 processed ready/cache、取消 pending render；舊完成 callback 不可覆蓋新模式／新選取。RAW 演算法及 native BaselineExposure 沒有更動。
- Camera cache 與 processed handoff 分離，包含主檔及 companion 的 fresh stat revision；沿用 bounded thumbnail cache，不建立多張無界限 full-resolution RAW holders。

### Develop：既有 accurate 編輯流程

- 使用既有 RAW holder／WB／色彩／Highlights／crop pipeline，套用保留的 XMP。
- 準備 accurate frame 時仍可先看過渡 JPEG，畫面明示 **Preview — preparing accurate Develop**（可能是 JPEG、draft 或既有 cached preview）；不能把過渡 JPEG 標成已完成 accurate RAW。
- 已開始的同步 Core Image draw／ImageIO 工作不能強制中斷；取消的用途是阻止後续工作及舊 publication，不是保證已開始的解碼立即消失。
- Grid／Filmstrip thumbnails 本版始終為 camera preview；精確編輯結果在 Develop 主圖查看。Export 仍使用既有 accurate pipeline＋XMP，不改成匯出相機預覽。

## Histogram

- 右側 Histogram 內的 checkbox 是明確、persistent 的使用者開關；新 bundle 預設 off。**折疊 section 不等於關閉 histogram。**
- Off 不啟動 source load、RAW render 或 bin task，取消 pending bins 並釋放 histogram 結果／標籤。已顯示的單張 bitmap 仍是 viewer 的共用 frame，供重新開啟 toggle 使用，不是另外保留 RAW source。
- On：Library／Grid 直接 bin 當下顯示 JPEG bitmap，標示 **JPEG / camera preview — not RAW clipping**。
- Develop 等已完成 developed bitmap，再直接 bin 該 frame；不另開一遍 RAW decode／processed render。準備中的 JPEG 不會被當成 accurate histogram。
- Histogram 是 display RGB histogram，並不是感光元件 linear RAW clipping histogram。快速切片用 revision／cancel 擋舊結果；已開始的 CGContext draw 無法搶占，bin loop 支援合作取消。

## 背景 Trash：安全與限制

1. Backspace／選单仍先確認，不直接刪除。
2. 確認後立刻標記 pending，顯示 `Trash: N pending`，可立即看下一張；尚未成功的照片不提前宣稱已刪除。
3. 同一 serial background file queue 處理 Trash 與 XMP writes。MainActor 只更新狀態／publication；開始前設 write fence、取消該組 live／debounced XMP。已經在跑的 write 先完成，然後才在 worker 上列舉 RAW／JPG／basename XMP／direct XMP／companion XMP。
4. 僅呼叫 macOS Trash；failure 不會 fallback 到 permanent remove。每次 move 後確認 source 已不存在，並保持額外 security-scope leases 到 worker 結束。
5. 成功才移除 group；失敗 group 保留並報出失敗檔及已移進 Trash 的檔。Worker 若發現 primary 不存在／無法存取（例如 volume 離線），整組保留且不繼續移動 companions，不把 unavailable 誤報成功。新的使用者選取不會被晚到 completion 搶走。pending IDs／整組 related-member IDs／成功 tombstones／失敗保留 snapshot 防 watcher 重新插入舊資料；RAW 部分失敗時，殘留 JPG 也不能變成復活的 standalone asset。
6. **同一組 associated files 不具原子性。** 部分失敗時，先在 Finder 復原已移動檔，再重試。失敗組的 sidecar writes 在這個 app session 內仍隔離；復原完成後重開 App 才重新開放一般寫入。成功 tombstones 同樣只維持本 session；Finder 復原後可重開 App 重新掃描。
7. 下一張 metadata 可立即改記憶體狀態，但磁碟 XMP write 可能排在正在進行的 Trash 後；連原本 synchronous 的 Advanced checkbox 在 pending Trash 時也改為 queued，不讓 MainActor 等待 Trash。不要在有 pending Trash／XMP 時強制關閉 App；本版沒有持久 transaction journal／自動 Finder 復原。
8. 沒有拿使用者原始照片測刪除時間，也不宣稱 ExFAT Trash 已量測。刪除測試只用 disposable scratch fixtures。
