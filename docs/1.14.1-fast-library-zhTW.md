## 根因與最小修正

1. **大量 UI collection 重算**：Grid / Filmstrip 每個 context menu 在建立時會讀 selectedAssets / displayedAssets。原本每次都重新 filter / sort 整個資料夾，變成近似平方級 MainActor 工作。改為 collection / selection snapshot cache；allAssets（含 nested XMP mutation）、filter、sort、pending / completed Trash、selection 全部明確 invalidation。
2. **照片 identity 不是純記憶體讀取**：原 `PhotoAsset.id` 每次呼叫 `URL.standardizedFileURL.path`。實際 macOS sample 顯示會進到 Foundation reachability、stat、faccessat；UI 重複 identity 查詢會在外接 SSD 做同步 filesystem 工作。改在 PhotoAsset ingestion 時只計算一次，同樣保留 canonical ID。
3. **普通點擊 zoom 生命週期**：原單擊只在 mouse down 暫時 held zoom；mouse up 立刻回 Fit，取消尚未完成的 native RAW request。Library 改成完成短 click 時持續切換 Fit / native，drag 不切回 Fit。Develop 的 held / double-click RAW inspection 不改。

## Library 100% 的新行為

- 普通左鍵短 click：Fit ↔ 100%；100% 時 held drag 可 pan。Z / zoom button 仍可切換。
- 100% **優先讀 scanner 同資料夾、同 basename 配對的原始 JPG/JPEG**，按原圖像素解碼，不套用 Develop edits。
- 沒有配對 JPG 時，RAW embedded JPEG 必須實際與 source 的完整像素尺寸相符才可作為 native；小型 embedded preview 不放大假稱 100%，也不偷偷解 RAW。不可用時明示 Native JPEG unavailable，可回 Fit 或切 Develop。
- 原圖像素 / backing scale 決定 native 尺寸；例如 9504px 在 Retina 2× 顯示為 4752 points，再以 viewport 裁切與 pan。
- Native camera cache 為 memory-only，NSCache count limit 2 / cost limit 512MiB；與 thumbnail cache 分開，不預解碼一整個資料夾 full-size JPG。
- Native request 有取消檢查、selection / mode source revision / load ticket guard；同步 ImageIO 已開始的工作仍不能硬搶占，但過期結果不可發布。
- Native JPEG 使用獨立 serial foreground decode queue，不排在 Grid thumbnail decode queue 後面。
- Develop 仍是 accurate RAW + XMP、native / ROI inspection。相機 JPEG 不標為 developed RAW，兩模式的亮度 / WB 差不代表 RAW 演算法被改。

## 實測：真正 hosted viewport，不是 19ms service bitmap 推算

使用唯讀實際資料夾：
`$LUMIBASE_A7RV_FIXTURE`（由使用者指定自己的唯讀配對測試資料夾）

739 個 RAW+JPG assets，1100×740 window，真正 Workspace / LazyVGrid / Loupe / Filmstrip；native clip viewport 移到 46–56% 中段；三次 Grid → single → Grid，每次 rapid arrows 八次。主 run-loop 10ms heartbeat 和實際 bitmap publication 分開量測。

- 原始 1.14.0 debug probe 超過 420 秒未完成。主 thread sample 指向 lazy layout → Grid context menu → selectedAssets / displayedAssets → PhotoAsset.id → Foundation filesystem reachability / stat。
- 為取得可比較數字，Release diagnostic build **只恢復 1.14.0 的 uncached collection / computed ID 路徑**，其他修正保留；相同 739 assets / 實際 Workspace。heartbeat 記錄 **12,138ms** 與 **57,864ms** stall，Grid→single 超過 8 秒仍無 ready bitmap、assertion RED。後續仍卡頓，因此中止該診斷 run，沒有捏造完整 baseline JSON。
- 最終 1.14.1 Release：最大 heartbeat gap **149.3ms**，p95 **103.7ms**。先前獨立 Release run 最大 198.2ms；不是宣稱每幀順暢或已達 60fps。
- Grid→single 實際第一張 bitmap：**113.8–129.1ms**（三次）。Rapid arrow 過程觀察到的 20 次 publication：**32.1–57.0ms**；快切會合法取消中間請求，最終 active ID 必須相符。
- Library 普通短 click、mouse up 後實際 native frame：**9504×6336 JPEG**，Retina backing **2.0**，約 **197.2ms**；驗證 drag 不回 Fit、第二次短 click 回 Fit。Library click probe RAW source-load 與 histogram bin count 都為零。
- 另做四張真實 A7RV hosted Library / Develop 前後切換：Develop accurate first-ready 約 **611–730ms**；從 native JPEG 切 Develop 後驗證 accurate RAW/native ROI frame，不允許 JPEG 沿用為 accurate。

量測不是 compositor present，也不是使用者實體滑鼠的逐幀錄影；OS / thumbnail cache 未清空。FolderScanner quickScan 真實 739 assets，但大型 viewport probe 未併行 full metadata scan / watcher event storm；Left Sidebar / Right Inspector 未包含在這個 hosted Workspace probe。因此仍需實際使用者回測，不能聲稱所有 folder size / 冷 cache / 背景 rescan 情況都已無卡頓。

## 已知限制

本版先修復已證明最大的 MainActor 平方級工作與 Library click/native 問題。仍有最高約 150–200ms 的 layout / UI stall；不是零 stutter。Thumbnail 任務 storm / disk-cache lazy raster、冷啟動與 full metadata scan / watcher concurrent workload 尚未做完整 priority scheduler 改造或長時間 profiling。Native ImageIO 同步解碼不可即時中止，NSCache limits 不是整個 process 的硬 RSS 上限。沒有 full-size JPEG 時只能明示不可用，不以低解析 preview 冒充 100%。
