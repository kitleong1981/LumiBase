# LumiBase Fast Library 1.14.7

## 原生 Settings

按 **⌘,**（LumiBase Fast Library → Settings），展開 **Performance / Cache**。

- **Library JPEG ROI — Experimental**：OFF（全新偏好設定預設）、前後各 1 張、前後各 2 張。使用者明確選擇後會在重啟時保留。
- **ROI cache budget**：64 / 128 / 256 MiB，與鄰居範圍獨立設定。±2 最多四個鄰居，不保證四個都能放入 64 MiB。
- 顯示快取 entries / MiB，**Clear ROI cache** 可取消尚未發布的工作並清空。
- 設定變動會使舊工作失效並立即裁減快取；仍僅有一個 utility helper。只在 Library 的原生 100% 檢視完成後產生鄰居 ROI，不在 Grid / Fit 解碼、不預存完整鄰居 native bitmap，也不是 Develop RAW ROI。

預算包含 ROI 與同張照片的低解析 fallback，**不是 App + helper RSS 上限**。短命 helper 仍需完整 JPEG 解碼，冷啟動瞬間可約 750 MB；先前 ±1 實測部分首次原生顯示改善，但暖 native hit 可能更快，記憶體可能增加。保留實驗標示與預設 OFF，不宣稱所有照片或平台加速。

保留既有 Library / Develop 工作區、按住左鍵 100%／放開 Fit、Trash 確認安全、RAW 基準、metadata / histogram 關閉時的安全性。

## 可攜式驗證

```sh
swift test -c release
# 使用自己的唯讀配對 A7RV fixture；不提交照片或私人完整路徑。
export LUMIBASE_A7RV_FIXTURE="/path/to/read-only/A7RV"
export LUMIBASE_JPEG_ROI_BENCH=on2 # off / on / on2 / pan / memory
export LUMIBASE_JPEG_ROI_BUDGET=128
export LUMIBASE_JPEG_ROI_REPORT="$PWD/roi-report.json"
swift test -c release --filter LibraryJPEGROIBenchmarkTests
```

目前配對 benchmark 使用 DSC01442–DSC01446 的 JPG/ARW，缺少 fixture 時跳過；合成 JPEG 的四鄰居／裁減／像素一致性測試不依赖私人檔案。舊有 mounted-folder 739 張固定假設若與實際動態目錄不同，應列為已知 fixture failure，不掩飾為全數通過。

±2 / 128 MiB 獨立 16-cycle helper memory probe：最後 8 次 parent RSS span **0.03125 MiB**，clear 後 owned ROI bytes **0**、parent RSS **231.98 MiB**。測試是特定受控 fixture，不代表所有全解析 JPEG 的 process RSS 硬上限。

三輪比較＋mounted suite 前後：當時 717 RAW assets，全部目錄檔名／size／mtime snapshot 與五組測試 RAW/JPEG 內容 SHA256 相同；其他使用者挑片時段的數量變動不歸因於本測試。
