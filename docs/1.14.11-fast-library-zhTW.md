# LumiBase Fast Library 1.14.11

## 啟動與重新開啟主視窗

修正 app 啟動只開 Settings、沒有照片主視窗。`LumiBaseApp` 原將 `Settings` 宣告在 `WindowGroup` 前，SwiftUI 將它當成預設啟動 scene；即使使用 `-ApplePersistenceIgnoreState YES` 排除視窗還原，1.14.10 仍只開 Settings（AX workspace count=0）。把主 `WindowGroup` 放在前面、Settings 保留於後即可修正預設啟動。

另外實際重現：只改 scene 順序後，關閉主視窗但保留 Settings，再用 Finder／Dock 類型的 `open` 重新開啟，仍只有 Settings。現在主 scene 具備 `workspace` ID，AppKit delegate 在**明確 reopen** 時先找已註冊的主 NSWindow，否則才 `openWindow(id:)`。弱參照註冊不改 SwiftUI 自己的 window restoration identifier；pending request 合併，初次 launch 交給預設 scene，避免啟動與 reopen 重複建立主窗。一般 activate、不操作 Settings、不故意關閉主窗後的等待，都不會強制開主窗。

沒有清除 UserDefaults、停用整個 app 的視窗還原、修改 ROI／sharpness／照片或鍵盤路由。保留前版 HOLD 點擊錨點、release→Fit、Z／完成雙擊、Trash sheet、processed Library 與 full-resolution score。
